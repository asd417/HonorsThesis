\section{PuzzleJAX}
The PuzzleJAX framework, developed by Julian Togelius et al., represents a significant shift in how puzzle-solving agents are trained and evaluated in artificial intelligence research. It is a high-performance, GPU-accelerated benchmark designed specifically to facilitate AI reasoning within combinatorial puzzle environments. By leveraging the JAX library, the framework allows for massive parallelism and end-to-end differentiability, enabling the simulation of thousands of environments simultaneously on a single accelerator.

\section{Boxoban}
The PuzzleJAX environment is utilized to load the Boxoban dataset, a collection of 9 million procedurally generated Sokoban levels released by Google. These levels are constrained to a $10\times10$ grid, providing a standardized yet vast state space for evaluating an agent's ability to generalize across millions of unique configurations.

\section{Pruning Breadth-First Search}
Generating solution trajectories for the Boxoban dataset requires a search method that is both complete and practical at scale. A standard breadth-first search applied to the full Sokoban state space is computationally intractable because many branches lead to deadlock configurations that can never reach a solution, causing the search frontier to grow unnecessarily large. To make BFS feasible, we implement a deadlock detection step that prunes any branch in which a box has been pushed into a corner position that is not a designated goal. Because such configurations are permanently unrecoverable, no solution can be found by continuing down that branch, and pruning it early avoids a large number of wasted node expansions. The resulting search produces compact, provably correct solution trajectories that serve as the supervised signal for training all three heuristic approaches.

\section{Trajectory and Divergent Trajectory}

All three heuristic approaches are trained on (state, cost-to-go) pairs. This approach to generating training data is directly inspired by the Autodidactic Iteration procedure of DeepCubeA \cite{agostinelli2019solving}, in which training states are generated by backward induction from the goal: beginning at the solved state, random action sequences of increasing length are applied, and each resulting state is labeled with the number of steps applied as its cost-to-go. This reverse-trajectory strategy is well suited to A* heuristics because it guarantees ground-truth distance labels without any forward search. A subsequent extension of DeepCubeA applying the same principle to Sokoban demonstrated that the reverse-trajectory dataset is sufficient to train heuristics capable of solving highly complex instances \cite{agostinelli2021admissible}.

In this work, solution trajectories are produced by the pruned BFS rather than backward scrambling, but the labeling principle is identical. Each BFS trajectory is a sequence of states from the initial configuration to the goal; state $s_i$ along a trajectory of length $T$ is assigned cost-to-go label $c_i = T - i$. The goal state receives label 0, the penultimate state receives label 1, and so on, so every state in the training set has an exact ground-truth cost-to-go.

To extend the coverage of the training distribution beyond the solution path, we generate divergent trajectories. From each state on a solution trajectory, each of the three non-solution actions is applied, producing a depth-1 off-path state. These divergent states are distinct from any state on the solution trajectory (verified by hash) and represent positions at which the agent has taken a suboptimal step. Including them in training gives the heuristic examples of states that are further from the goal than the solution path alone would suggest, improving its ability to assign appropriately high cost estimates to states that have departed from the optimal route.

\section{Heuristic Approaches}

All three approaches share the same input representation and evaluation protocol. The input to each heuristic is the flattened multi-hot grid state $s_t \in \{0,1\}^{500}$, a $(5 \times 10 \times 10)$ binary tensor encoding walls, boxes, goals, and the player. Each heuristic outputs a scalar estimate $\hat{h}(s_t)$ of the remaining steps to solution. Node expansion during Weighted A* search is prioritized by:

$$f(s_t) = g(s_t) + w \cdot \hat{h}(s_t)$$

where $g(s_t)$ is the cost incurred from the start and $w \geq 1$ trades solution optimality for search speed. The three approaches differ in how $\hat{h}$ is parameterized and optimized.

\subsection{NEAT}

The NEAT heuristic evolves both the weights and topology of a feed-forward network from scratch. The genome is initialized with 500 input nodes, 1 output node, zero hidden nodes, and a 5\% sparse partial direct connection from inputs to the output --- approximately 25 connections at initialization. Each genome is evaluated against the full training set every generation, computing fitness as the negative MAE over all $N$ training states:

$$\text{fitness} = -\frac{1}{N}\sum_{i=1}^{N} |\hat{c}_i - c_i|$$

This matches the data exposure of the CNN baseline, which also processes the entire training set each epoch, ensuring that any accuracy difference between the two approaches reflects model capacity rather than data access. Structural mutations (add-node, add-connection) grow the network only where doing so improves fitness, and speciation protects innovations from being discarded before their weights can be refined.

The initial genome has approximately \textbf{26 parameters} (25 connection weights and 1 output bias). The winner genome after evolution is expected to remain in the range of tens to a few hundred parameters --- several orders of magnitude smaller than the CNN baseline.

\subsection{CoDeepNEAT}

CoDeepNEAT coevolves two NEAT populations: \textit{modules} (individual dense-dropout blocks) and \textit{blueprints} (topology graphs whose nodes point to module species). During each generation, blueprints and modules are assembled into complete Keras models, each of which is trained for a fixed number of gradient-descent epochs on a subsample of training data. Fitness is assigned as $1/(1 + \text{val\_MAE})$, with fitness attributed back to both the blueprint and all modules that participated in the assembled genome.

The module search space constrains each Dense layer to between 64 and 512 units (step 64), with an optional dropout layer (rate 0--0.3). Blueprint mutation can add or remove nodes, so the depth of the assembled network grows through evolution. Representative parameter counts for plausible evolved topologies are:

\section{Fitness Functions}

\paragraph{CNN.} Trained by gradient descent to minimize asymmetric Huber loss on batches of (state, cost-to-go) pairs, with overestimation penalized at $2\times$ to bias toward admissibility.

\paragraph{NEAT.} Each genome evaluated on the full training set every generation. Fitness $= -\text{MAE}$.  Best genome by validation MAE is checkpointed.

\paragraph{CoDeepNEAT.} Each assembled genome is gradient-trained for 5 epochs on a subsample of 8,192 states, then evaluated on the full validation set. Fitness $= 1/(1 + {val\_MAE})$.  Best model by validation MAE is checkpointed.
