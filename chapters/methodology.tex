\section{Boxoban}

All levels of the Boxoban puzzle set are constrained to a $10\times10$ grid, providing a standardized yet vast state space for evaluating an agent's ability to generalize across millions of unique configurations. Boxoban is partitioned by Google into \emph{unfiltered}, \emph{medium}, and \emph{hard} difficulty splits; this thesis draws every puzzle, both training and evaluation, from the \emph{medium} split, so both distributions are matched in difficulty.

From the medium split, 14{,}000 puzzles were sampled and solved with the pruned BFS described in the next section to form the training set, and a disjoint set of 294 puzzles from the same medium split was held out as the evaluation set. Although Boxoban contains roughly nine million levels in total, this thesis does not use the full corpus: a CNN data-scaling sweep (Figure~\ref{fig:cnn_scaling_solve}) shows that solve rate plateaus once the training set reaches a few thousand levels, so 14{,}000 was chosen as a point well past the plateau while remaining tractable to solve with BFS within available compute. All three heuristics --- CNN, NEAT, and CoDeepNEAT --- are trained on the same 14{,}000-level training set and evaluated on the same 294-level held-out set, so any difference in solve rate reflects model capacity rather than data access.

\section{Reverse Trajectory and Cost-to-Go Labels}

In order to generate the reverse trajectory for labelled cost-to-go dataset, a set of Boxoban puzzles were solved with a pruned breadth-first search (BFS) algorithm. A standard breadth-first search applied to the full Sokoban state space is computationally intractable because many branches lead to deadlock configurations that can never reach a solution, causing the search frontier to grow unnecessarily large. 
To make BFS feasible, we implement a deadlock detection step that prunes any branch in which a box has been pushed into a corner position that is not a designated goal. Because such configurations are permanently unrecoverable, no solution can be found by continuing down that branch, and pruning it early avoids a large number of wasted node expansions. 

Each BFS trajectory is a sequence of states from the initial configuration to the goal; state $s_i$ along a trajectory of length $T$ is assigned cost-to-go label $c_i = T - i$. The goal state receives label 0, the penultimate state receives label 1, and so on, so every state in the training set has an exact ground-truth cost-to-go.

The resulting search produces compact, provably correct solution trajectories that serve as the supervised signal for training all three heuristic approaches. This provides a rich dataset of (state, cost-to-go) pairs for training heuristics to estimate the distance to solution from any given configuration. This approach to generating training data is directly inspired by the Autodidactic Iteration procedure of DeepCubeA \cite{agostinelli2019solving}. All three heuristic approaches are trained on the (state, cost-to-go) pairs. This reverse-trajectory strategy is well suited to A* heuristics because it guarantees ground-truth distance labels without any forward search. A subsequent extension of DeepCubeA applying the same principle to Sokoban demonstrated that the reverse-trajectory dataset is sufficient to train heuristics capable of solving highly complex instances \cite{agostinelli2021admissible}. This training data was used for all three following heuristic approaches, ensuring that any performance difference reflects the model's ability to learn from the same underlying signal rather than differences in data access or quality.

\section{Heuristic Approaches}

The three approaches share the same input representation and evaluation process. The input to each heuristic is the flattened multi-hot grid state $s_t \in \{0,1\}^{500}$, a $(5 \times 10 \times 10)$ binary tensor encoding walls, boxes, goals, and the player. Each heuristic outputs a scalar estimate $\hat{h}(s_t)$ of the remaining steps to solution. Node expansion during Weighted A* search is prioritized by:

$$f(s_t) = g(s_t) + w \cdot \hat{h}(s_t)$$

where $g(s_t)$ is the cost incurred from the start and $w \geq 1$ trades solution optimality for search speed. The three approaches differ in how $\hat{h}$ is parameterized and optimized.

\subsection{CNN Baseline}

The CNN baseline is a fixed-topology convolutional network trained by gradient descent (AdamW with cosine learning rate schedule and asymmetric Huber loss that penalizes overestimation more heavily to bias the heuristic toward admissibility) \cite{loshchilov2017decoupled}. \subsection{NEAT}

The NEAT heuristic evolves both the weights and topology of a feed-forward network from scratch. The genome is initialized with 500 input nodes, 1 output node, zero hidden nodes, and a 5\% sparse partial direct connection from inputs to the output which is approximately 25 connections at initialization. Each genome is evaluated against the full training set every generation, computing fitness as the negative MAE over all $N$ training states:

$$\text{fitness} = -\frac{1}{N}\sum_{i=1}^{N} |\hat{c}_i - c_i|$$

This matches the data exposure of the CNN baseline, which also processes the entire training set each epoch, ensuring that any accuracy difference between the two approaches reflects model capacity rather than data access. Structural mutations (add-node, add-connection) grow the network only where doing so improves fitness, and speciation protects innovations from being discarded before their weights can be refined.

The initial genome has approximately \textbf{26 parameters} (25 connection weights and 1 output bias). The winner genome after evolution is expected to remain in the range of tens to a few hundred parameters which is several orders of magnitude smaller than the CNN baseline.

\subsection{CoDeepNEAT}

CoDeepNEAT coevolves two NEAT populations: \textit{modules} (individual dense-dropout blocks) and \textit{blueprints} (topology graphs whose nodes point to module species). During each generation, blueprints and modules are assembled into complete Keras models, each of which is trained for a fixed number of gradient-descent epochs on a subsample of training data. Fitness is assigned as $1/(1 + \text{val\_MAE})$, with fitness attributed back to both the blueprint and all modules that participated in the assembled genome.

The module search space constrains each Dense layer to between 64 and 512 units (step 64), with an optional dropout layer (rate 0--0.3). Blueprint mutation can add or remove nodes, so the depth of the assembled network grows through evolution. Representative parameter counts for plausible evolved topologies are:

\section{Training Metrics}

The CNN was trained with a loss function for minimizing the Huber loss \cite{huber1992robust} on batches of (state, cost-to-go) pairs, with overestimation penalized at $2\times$ to bias toward admissibility. 

NEAT and CoDeepNEAT uses a fitness function to train the network either fully or partially. The fitness function of NEAT was $= -\text{MAE}$ and the best genome by validation MAE is checkpointed. 

CoDeepNEAT uses $MAE$ as the loss function for the gradient descent and uses $1/(1 + {val\_MAE})$ as the fitness function for evolving the network architecture with NEAT.
